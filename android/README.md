# Starcluster под Android — проверка концепции

Игра целиком собирается и запускается на Android: тот же C++, тот же SDL2, те же
24 файла исходников, что и на маке. Это ПРОВЕРКА КОНЦЕПТА, а не порт: управление
сделано самым дешёвым способом, каким можно было обойтись без нового кода —
системной экранной клавиатурой.

## Как собрать

```sh
./setup_toolchain.sh   # разово: JDK уже из homebrew, качает SDK+NDK+эмулятор (~9 ГБ)
./build_apk.sh         # apk -> app/build/outputs/apk/debug/app-debug.apk
```

Исходники SDL2 и SDL2_mixer не в репозитории; `deps/` набивается так:

```sh
mkdir -p deps && cd deps
curl -LO https://github.com/libsdl-org/SDL/releases/download/release-2.30.10/SDL2-2.30.10.tar.gz
curl -LO https://github.com/libsdl-org/SDL_mixer/releases/download/release-2.8.0/SDL2_mixer-2.8.0.tar.gz
tar xzf SDL2-2.30.10.tar.gz && tar xzf SDL2_mixer-2.8.0.tar.gz
cd .. && ln -sfn ../../deps/SDL2-2.30.10 app/jni/SDL
ln -sfn ../../deps/SDL2_mixer-2.8.0 app/jni/SDL2_mixer
```

Запуск на эмуляторе:

```sh
$ANDROID_HOME/emulator/emulator -avd starcluster &
$ANDROID_HOME/platform-tools/adb install -r app/build/outputs/apk/debug/app-debug.apk
$ANDROID_HOME/platform-tools/adb shell am start -n org.starcluster.game/.StarclusterActivity
```

## Что пришлось изменить в самой игре

Три места, все под `#ifdef __ANDROID__`, десктопные сборки не задеты:

1. `main.cpp:1` — `SDL_MAIN_HANDLED` теперь только не-Android. Java-активность
   ищет в библиотеке функцию `SDL_main`, а это макро как раз отменяет
   переименование, которое делает `SDL_main.h`.
2. `assetPath()` — на Android ищет ассеты там, куда их распаковал
   `AndroidPort::extractAssets()`.
3. Опрос удержания клавиш (`gameKeyboardState()`) — обёртка вокруг
   `SDL_GetKeyboardState`, на Android подмешивает залипшие нажатия.

Плюс новый `android/support/android_support.cpp` — весь Android-слой.

## Три грабли, на которые уже наступили

**Ассеты внутри apk.** `assetPath()` ходит через `fopen`, а музыка
перечисляется через `dirent` — ни то, ни другое не видит содержимое apk (это
zip). Поэтому при первом запуске 12 файлов копируются наружу, в
`SDL_GetPrefPath`, и дальше игра работает с обычными файлами. Список файлов
прибит гвоздями в `ASSETS` (`android_support.cpp`) и продублирован в
`stageAssets` (`app/build.gradle`) — новый ассет надо добавить В ОБА МЕСТА.

**Игровой `features.h` ломает libc++.** ndk-build молча добавляет `LOCAL_PATH` в
пути поиска заголовков. Если направить `LOCAL_PATH` в корень репозитория, то
`#include <features.h>` внутри `<__config>` найдёт игровой файл вместо
системного, и стандартная библиотека развалится с сотней ошибок в
`integral_constant.h`. Поэтому `LOCAL_PATH` оставлен в `jni/src`, а к исходникам
ведёт `../../../..`: заголовки игры всё равно находятся, потому что
`include "game.h"` ищется рядом с самим исходником.

**SDL2_mixer тянет wavpack.** В релизном тарболе `external/wavpack` нет (только
`download.sh`), а `SUPPORT_WAVPACK` по умолчанию включён. Гасится аргументом
`SUPPORT_WAVPACK=false` в `app/build.gradle`; mp3 играет встроенный minimp3.

## Управление: что работает и что нет

Экранная клавиатура поднимается при старте и держится поднятой — она и есть
управление. SDL сам превращает набранные символы в `SDL_KEYDOWN` со скан-кодами,
так что игровые привязки работают без единой правки.

Работает:

* все буквенные и цифровые хоткеи: L, G, T, B, V, E, U, M, C, O, I, R, 1–4, 0;
* Enter и пробел;
* полёт (W/A/S/D/Q/E/R/F) — через залипание: тап даёт импульс на 250 мс;
* весь оконный интерфейс пальцем: SDL шлёт касания как клики мыши, и кнопки
  нижней панели, списки и окна нажимаются как есть;
* звук: музыка играет через OpenSL ES.

Не работает — этих клавиш на клавиатуре IME просто нет:

* стрелки (панорама карты, выбор элемента);
* F1/F2/F5/F9 — справка, выкуп лицензии, сохранение и загрузка;
* `[` и `]` — перебор элементов;
* Shift (варп), Tab (следующий агент);
* ESC достаётся только системной кнопкой «назад».

Клавиатура занимает примерно 40% экрана, а строка подсказок IME копит
набранные буквы («lwwwwwwww») — косметика, но видно.

## Замеры на эмуляторе (Pixel 5, arm64, программный GPU)

* карта скопления, 8192 системы: ~19 кадров/с;
* локальный режим (звезда, планеты, попиксельная плазма): ~28 кадров/с.

Эмулятор рисует программно, так что это НИЖНЯЯ оценка, а не оценка телефона.
