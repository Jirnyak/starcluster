## 2. ЖЁСТКИЕ АРХИТЕКТУРНЫЕ ОГРАНИЧЕНИЯ (CRITICAL)

Эти правила повторяются во всех `plans_*.md`. Нарушение ломает стиль/детерминизм проекта.

1. **Data-oriented design. НИКАКОГО ООП-наследования, `virtual`, новых классов-иерархий,
   `new`.** Только C-style `struct`, непрерывные `std::vector`, числовые id/индексы.
   Логика — свободные функции над данными.

2. **Только C++11 и только SDL2.** Никаких сторонних библиотек, никакого C++14+ синтаксиса
   (проверяется флагом `-std=c++11`).

3. **Детерминированный глобальный ГПСЧ.** Есть `extern std::mt19937 rng;` и
   `int randomer(std::mt19937&, int max)` — ВКЛЮЧИТЕЛЬНЫЙ диапазон `[0, max]`.
   - **Локальный режим НЕ трогает глобальный `rng`** (это рассинхронизировало бы макро-симуляцию).
     Для локальной случайности заводи **свой** `std::mt19937`, засеянный от сида звезды/индекса.

4. **Правило CHROMOCORE (запекание).** Материалы/кинематика/тактика уже ЗАПЕЧЕНЫ в поля
   корабля (`cargoCapacity, maxHullHP, speed, acceleration, heavyWeapons, lightWeapons,
   armor`). Код, читающий корабль (в т.ч. локальный), **читает СЫРЫЕ поля и НЕ домножает их снова**.

5. **Кастомный 5×7 битмап-шрифт.** Каждый глиф — строка ровно **35 символов** ('0'/'1'),
   5 столбцов × 7 строк. Горизонтальный шаг пера `6*scale`, вертикальный `8*scale`. Текст
   авто-переводится в ВЕРХНИЙ регистр. Таблица глифов — единственная, в `render2d.cpp::glyph()`.
   ⚠️ Если добавляешь символ — строка ДОЛЖНА быть 35 символов (иначе out-of-bounds в `drawText`, см. §6.3).

6. **printf-формат в ВЕРХНЕМ регистре:** `%.0F`, `%.2F`, `%d` (шрифт всё равно капсит).

7. **Ортографическая 3D→2D проекция** (без деления на перспективу). `depth` — только для
   порядка отрисовки (painter) и затухания (fade). См. `camera.h`.

## 3. Сборка, запуск, тесты

```bash
make                       # сборка -> ./game  (см. Makefile, SOURCES перечисляет все .cpp)
./game                     # запуск игры (SDL-окно)
make asan                  # санитайзер-сборка -> ./game_asan (ASan+UBSan, для проверок §3.1)
make soak                  # собрать и прогнать soak-тест локального режима (§6.5)
make clean                 # удалить бинари (game, game_asan, soak_asan, *.dSYM)

# Smoke-тесты (headless, для CI/проверки без окна):
SDL_VIDEODRIVER=dummy ./game --smoke        # макро-путь: 12 кадров, ожидаемый exit 0
SDL_VIDEODRIVER=dummy ./game --localsmoke   # локальный путь: авто-вход в систему,
                                            # инъекция ввода (огонь/добыча/тяга/варп), exit 0
```

Компилятор: `c++ … -O3 -std=c++11 -I/opt/homebrew/include/SDL2 -D_THREAD_SAFE -L/opt/homebrew/lib -lSDL2`.

### 3.1 Проверка памяти (ASan/UBSan) — делай это для нового кода
```bash
make asan                                                                    # -> ./game_asan (цель в Makefile)
SDL_VIDEODRIVER=dummy ASAN_OPTIONS=detect_leaks=0 ./game_asan --localsmoke   # exit 0, 0 ошибок
SDL_VIDEODRIVER=dummy ASAN_OPTIONS=detect_leaks=0 ./game_asan --smoke        # ~1.5 мин под ASan, exit 0

ASan под `--smoke` идёт долго (~90 с) из-за тяжёлой макро-симуляции — это НЕ зависание.
Для локального режима есть ещё `make soak` — детерминированный soak-тест на тысячи кадров (§6.5).

clangd в редакторе пишет `'SDL.h' file not found`, `Unknown type name 'SDL_Color'/'SDL_Rect'/'Uint8'`,

## 5. Локальный режим полёта («микромир») — главный незакрытый трек

### 5.1 Идея
Поверх макро-кластера игрок «ныряет» в одну звёздную систему (или в пустой глубокий космос)
и летает в **реальном масштабе**, инерционно (как в Elite). Звезда в центре, планеты по
кеплеровым орбитам, пояс астероидов, другие корабли, **живой бой**, **добыча руды на месте**,
**стыковка с планетой = рынок**. Пустота между звёздами в основном пуста, но бой и события работают.

### 5.2 Решения пользователя (зафиксированы, не переоткрывать)
1. **Полёт = инерционный (Elite-style):** тяга + дрейф, не «аркадный доворот».
2. **Вход в режим — в любой момент** (клавиша `L`).
3. **Первый срез обязан включать ВСЕ ЧЕТЫРЕ:** (а) другие корабли летают, (б) добыча астероидов
   на месте, (в) живой бой, (г) стыковка с планетой = рынок. — Сделано.
4. **Темп = «долго + автопилот-ускорение»:** реалистично большие расстояния; удержание `Shift`
   ускоряет течение времени (supercruise-подобный варп ×60).

### 5.3 Единицы и время
- Пространство: **LU** (local units). Время: локальные **ЧАСЫ**.
- Базовый темп: `1 реальная сек = HOURS_PER_SEC (=1) локальный час`. Удержание варпа умножает поток
  времени на `WARP_MULT (=60)`.
- Орбиты кеплеровы: `orbitSpeed ~ 40 / r^1.5`. Позиции тел пересчитываются из `localHours` каждый кадр.
- Физика идёт **субшагами** (чтобы снаряды не «протуннелировали» цель под варпом):
  `N = clamp(ceil(dtHours/0.05), 1, 64)`, шаг `h = dtHours/N`.

### 5.4 Тюнинг (`namespace LocalCfg` в `local.h`) — крутилки баланса

PLAYER_ACCEL    = 30.0    PLAYER_MAXSPEED = 95.0    TURN_RATE = 2.4 (рад/реальную сек)
DOCK_RANGE      = 26.0    MINE_RANGE      = 20.0
PROJ_SPEED      = 520.0   PROJ_LIFE_HOURS = 1.2     WEAPON_RANGE = 150.0   FIRE_COOLDOWN_H = 0.10
SHIELD_REGEN_DELAY_H = 3.0   SHIELD_REGEN_RATE = 7.0/ч   PLAYER_SHIELD_BASE = 22.0 (+ armor*1.5)
LOOT_SCOOP_RANGE = 24.0   LOOT_LIFE_HOURS = 300.0   NPC_BOOST_MULT = 1.8 (форсаж при бегстве)
RADIO_REVEAL_RANGE = 300.0 (×(1+0.6*tier))   RADIO_CLAIM_RANGE = 36.0   FX_MAX = 3600 (жёсткий потолок пула частиц)
```
Прочие числа баланса (в коде): урон игрока `heavy*0.6 + light*0.4 + 2.0`; урон NPC `… + 1.0`;

### 5.5 Модель данных (`local.h`) — кратко
Перечисления: `LocalBodyKind { LB_ROCKY, LB_GASGIANT, LB_ICE, LB_STATION, LB_MOON }`,
`LocalCraftKind { CK_TRADER, CK_PIRATE, CK_PATROL, CK_CIVILIAN }`,
`LocalFxKind { FX_SPARK, FX_DEBRIS, FX_TRAIL, FX_RING, FX_MUZZLE, FX_SMOKE }`,
`LocalRadioKind { RS_DERELICT, RS_CACHE, RS_DISTRESS, RS_ANOMALY }`.
`constexpr int LOCAL_TARGET_PLAYER = -1000;` — sentinel «цель ИИ = игрок» для `aiTarget`.
- `LocalBody` — тело на орбите (orbitRadius/Phase/Speed/inclination, x/y/z, radius, kind, `parent`
  (для лун — индекс планеты, орбита считается вокруг неё), `ringInner/ringOuter` (кольца газовых
  гигантов), r/g/b, `hasMarket`, name).
- `LocalRock` — астероид, **двигается**: `orbitR/orbitAng/orbitVel` (пояс медленно вращается вокруг
  звезды) + `spin/spinVel` (собственное вращение); x/y/z пересчитываются каждый кадр; `ore/element/rgb`.
- `LocalCraft` — корабль: позиция/скорость/цель, maxSpeed/accel, hull, `shield/maxShield/shieldRegenTimer`,
  **сырые** heavy/light/armor, faction, `kind`, `agentIndex` (>=0 → зеркалит макро-агента), `hostile`,
  `aiState/aiTarget` (ИИ), `boost` (форсаж), `hitFlash/thrustGlow` (juice), таймеры, r/g/b, label.
- `LocalProjectile` — снаряд (позиция/скорость, life, damage, `team` 0=игрок/1=враг, rgb-трассер).
- `LocalFx` — частица (позиция/скорость, life/maxLife в часах, size, kind, rgb). Пул ≤ `FX_MAX`.
- `LocalLoot` — канистра из обломков (позиция/скорость, `element/amount`, life). Авто-сбор в зоне.
- `LocalRadioSource` — радиоисточник (x/y/z, `kind`, `tier` 0..2, `strength`, `reward/research/element/
  amount`, `revealed/resolved`, label). Ловится детектором ≥ своего тира.
- `LocalScene` — вся сцена: active, starIndex (-1 = deep space), hasStar, звезда, `localHours`,
  векторы bodies/rocks/craft/shots/**fx/loot/radio**, туманность (`nebulaRGB/nebulaStrength`),
  игрок (px..pz, pvx..pvz, pyaw, ppitch, fireCooldown, playerMaxSpeed/Accel,
  **pShield/pMaxShield/pShieldTimer, playerDestroyed, playerHitFlash**), `detectorTier` (из
  `game.tech.sensors`), `lockTarget`, `shake/fxClock` (тряска/анимация), miningRock/miningAccum,
  dockPrompt, toast/toastTimer, warping/thrusting.
- `LocalInput` — ввод за кадр: thrust/brake/yawL/yawR/pitchU/pitchD/fire/warp (удержания) +
  mineToggle/dock/cycleTarget (edge-фронты за 1 кадр).

### 5.6 Три контракта (реализации в трёх файлах)
```cpp
// localgen.cpp — детерминированно строит сцену. Сид: 0x9E3779B9u ^ uint32_t(starIndex)
//   (starIndex>=0), иначе 0xD1B54A35u. НИКОГДА не трогает глобальный rng. game — только чтение.
void buildLocalScene(const Game& game, int starIndex, LocalScene& scene);

// localsim.cpp — двигает сцену на кадр (dtReal — реальные сек). Мутирует и сцену, и game:
//   добыча/лут кладут элементы в трюм игрока (уважая cargoCapacity через shipCargoMass); бой меняет
//   money/hullHP; при hull<=0 ставит scene.playerDestroyed (обработка — в main.cpp, §5.7);
//   килл чужой фракции даёт adjustFactionRelation(-8); радио-клейм — money/research/элемент.
//   Возвращает индекс звезды для стыковки, иначе -1.
int updateLocalScene(Game& game, LocalScene& scene, const LocalInput& in, double dtReal);

// localdraw.cpp — рисует сцену и HUD. Камера сверху (yaw=pitch=0), центр = игрок, scale = зум.
//   Переиспользует camera.h-проекцию и render2d.h-примитивы (namespace UI).
void renderLocalScene(SDL_Renderer*, const Game&, const LocalScene&,
                      const View3D&, const CameraBasis&, int winW, int winH);
```

Генерация (`buildLocalScene`): звезда по `stellarClass`; 3–6 планет (rocky/gas/ice), крупнейшая
rocky получает `hasMarket`; при `population>0` добавляется STATION; пояс 45–89 астероидов (элемент
из `resourceFocus`, либо при `metallicTrait>0.6` fallback на индекс 25); 0–8 co-located макро-агентов
(сырые поля корабля; `hostile` если `type=="pirate"`; цвета фракций); 1–3 торговца, 0–2 пирата;
игрок стартует на `innermostR+120`, `pyaw=M_PI`. Deep space (`starIndex<0`): `hasStar=false`, 0–2 торговца, игрок в начале координат.

### 5.7 Интеграция в `main.cpp` (где искать)
- Инклюды: `camera.h`, `local.h` (после `ui.h`). Флаг `--localsmoke` (устанавливает `smoke=true; localSmoke=true`).
- Состояние (~строки 520–534): `LocalScene localScene; View3D localView; double localZoom=0.8;`
  edge-флаги `localMineEdge/localDockEdge/localTargetEdge`. При `localSmoke` — build + `active=true`
  + перенос игрока к `rocks[0]` для headless-покрытия добычи.
- Обработка клавиш (~640–673): `L` — вход/выход (anchor = currentStar игрока если пристыкован и
  `!enRoute`, иначе `selectedStar`, иначе `-1`). В активной сцене: `ESC` выход; `E/K/Tab` → edge;
  `+/-` → `localZoom` (clamp 0.05..40.0); затем `continue` (макро-клавиши подавляются).
- Апдейт (~776–811): при `localScene.active` собирается `LocalInput` из `SDL_GetKeyboardState`
  (W/S/A/D/R/F/Space/Shift) + edge-флаги → `updateLocalScene`. Follow-cam: `localView` центр=игрок,
  `scale=localZoom`. Возврат `dockStar>=0` → выход из локала + `UI::openTradeWindow`. Иначе если
  `!paused` → `advanceGame`. **Пока сцена активна, макро-симуляция ЗАМОРОЖЕНА.**
  При `localSmoke` в апдейт инъецируется синтетический ввод (огонь всегда; добыча на кадре 0;
  тяга с кадра 4; варп с кадра 6) — прогоняет все ветки headless.
- Рендер (~824–835): при активной сцене — `makeCameraBasis(localView)` + `renderLocalScene` +
  present + учёт smoke-кадров + пейсинг + `continue` (макро-рендер пропускается).
- **Аварийный прыжок (смерть игрока):** сразу после `updateLocalScene`, если `localScene.playerDestroyed`
  — выходим из локала, восстанавливаем `hullHP` до 30% max, списываем 20% денег, `lastEvent` + `pushNews`.
  Обрабатывается ПЕРЕД веткой стыковки (`dockStar>=0`).

L        вход/выход из локального режима (из макро — по выбранной/пристыкованной звезде)
W        тяга по носу        S  тормоз (гашение вектора скорости)

### 5.9 Осознанные упрощения (что ещё НЕ сделано — это не баги)
- Пока игрок в локальном режиме, **макро-симуляция заморожена** (`advanceGame` не вызывается);
  фон не идёт, «прошло N времени по выходу» пока нет.
- NPC-vs-NPC бой считается **прямым DPS** (не снарядами): индексы кораблей нестабильны под
  swap-pop удалением, хранить владельца по индексу — баг. Бой с участием игрока — настоящие снаряды.
- Луны/кольца/туманность — **косметика** (на физику/геймплей не влияют, только визуальная навигация).
- Что БЫЛО упрощением среза 1 и теперь СНЯТО — см. §5.10 (игрок убиваем, астероиды двигаются, радио есть).

### 5.10 Углубление после среза 1 (два прохода — реализованы и провалидированы)
Оба прохода правили тот же набор файлов (`localgen/localsim/localdraw` + интеграция в `main.cpp`),
собирались параллельно субагентами (§6.1) и прошли все уровни проверки, включая soak (§6.5).

**Проход 1 — ощущение + глубина симуляции:**
- **Juice/частицы:** пул `LocalFx` — следы двигателя, вспышки выстрела, искры/обломки/дым попаданий,
  большой взрыв при смерти корабля, пыль от добычи. Прозрачность/размер по life/maxLife. Потолок `FX_MAX`.
- **Экранная тряска:** `scene.shake` (пиксели), растёт на попаданиях/взрывах/смерти, затухает; в draw
  смещает копию камеры (HUD не трясётся).
- **Щиты:** у игрока и NPC. Поглощают урон до корпуса, регенерят через `SHIELD_REGEN_DELAY_H` со
  скоростью `SHIELD_REGEN_RATE`. База игрока `PLAYER_SHIELD_BASE + armor*1.5`.
- **Игрок убиваем:** пол `hullHP>=1.0` снят; при hull<=0 → `playerDestroyed` + взрыв + аварийный прыжок (§5.7).
- **Смышлёный ИИ:** цели пересчитываются каждый кадр по `kind` (пират→ближайшая жертва; патруль→пират;
  торговец/гражданский→бегство от пирата, иначе странствие). Сближение / страйф на дистанции / бегство
  с форсажем (`NPC_BOOST_MULT`) при низком корпусе; упреждение при стрельбе.
- **Лут:** обломки роняют `LocalLoot` (элемент + кол-во), дрейфуют/тают (`LOOT_LIFE_HOURS`),
  авто-подбор в `LOOT_SCOOP_RANGE` с учётом трюма.
- **Живые астероиды:** пояс медленно вращается вокруг звезды, камни крутятся.
- **Реакция фракций:** килл небандитского корабля → `adjustFactionRelation(-8)` + вся фракция в
  системе становится враждебной. Килл пирата — награда без штрафа репутации.

**Проход 2 — контент + глубокий космос:**
- **Луны:** `LB_MOON` с `parent`, орбита вокруг планеты (sim добавляет позицию родителя). В генерации
  добавляются ПОСЛЕДНИМИ, чтобы не сдвигать индексную арифметику пояса/промежутков.
- **Кольца планет:** `ringInner/ringOuter` у ~55% газовых гигантов; рисуются концентрическими окружностями.
- **Туманность:** `nebulaRGB/nebulaStrength`, детерминированно по системе; плоская подсветка + мягкие пятна.
- **Радио + детекторы:** `LocalRadioSource` (kind/tier/reward/research/element). `detectorTier` из
  `game.tech.sensors` (0/1/2 при <1.08 / ≥1.08 / ≥1.20). Проявляется в `RADIO_REVEAL_RANGE*(1+0.6*tier)`
  если `detectorTier>=tier`; клейм в `RADIO_CLAIM_RANGE` даёт деньги + исследование + элемент в трюм.
  HUD-радар (справа снизу) + мировые/краевые маркеры. Это закрывает §7.2.

## 6. Методология проверок (применяй ко всему новому коду)

### 6.1 Параллельная сборка субагентами (проверенный паттерн)
Крупную фичу дели на **несколько .cpp, по одному на субагента**, а общие заголовки/контракты/
интеграцию (`*.h`, `main.cpp`, `Makefile`) держи за собой (оркестратор). Так три файла
локального режима (`localgen/localsim/localdraw`) писались параллельно без конфликтов.
Каждый субагент валидирует свой файл в изоляции:
```bash
c++ -std=c++11 -I/opt/homebrew/include/SDL2 -D_THREAD_SAFE -fsyntax-only <file>.cpp
```
`-fsyntax-only` делает полный семантический анализ (ловит несуществующие имена/поля), но НЕ
линковку. Реальная проверка связок — `make`.

### 6.2 Уровни проверки (все должны быть зелёными перед сдачей среза)
1. `make` — сборка без ошибок.
2. `--smoke` (макро) и `--localsmoke` (локал) в обычной сборке → exit 0.
3. ASan+UBSan сборка + оба smoke → exit 0, **0 ошибок** (§3.1). Ловит то, что exit-0 не ловит.
4. `make soak` — детерминированный soak-тест локального режима под ASan/UBSan → exit 0, 0 инвариант-фейлов (§6.5).

### 6.3 Урок этой сессии (реальный баг, найденный ASan)
Глиф `'B'` в таблице шрифта был **30 символов вместо 35** → `drawText` читал за границей
строкового литерала (`global-buffer-overflow`). Баг был **латентным и в макро-режиме** (обычная
сборка его не ловит — только ASan). Исправлено; таблица теперь единственная (в `render2d.cpp`),
все 48 глифов проверены на длину 35:
```bash
grep -oE 'return "[01]+";' render2d.cpp | grep -oE '[01]+' | \
  awk '{ if (length($0)!=35) print "BAD ("length($0)"): "$0 }'
```
**Вывод:** для чужого/нового кода всегда прогоняй ASan; не доверяй одному exit 0.

### 6.4 Дисциплина
- `<task-notification>`, `<system-reminder>`, «task tools haven't been used» — это **автоматические
  события, НЕ ввод пользователя**. Не считай их подтверждением/согласием.
- Убирай за собой временные артефакты (`game_asan`, `soak_asan`, `*.dSYM`) — `make clean` их сносит.

### 6.5 Soak-тест локального режима (`make soak`, файл `soak_test.cpp`)
Зачем: 12-кадровые headless-smoke почти не двигают время и всегда идут по CASE B генерации, поэтому
НЕ покрывают глубокий космос, многооборотные луны, радио-клейм/бой/смерть. Soak — отдельная `main()`
(линкуется с `LIBSOURCES`, без `main.cpp`), гоняет `updateLocalScene` по ~10 системам + глубокому
космосу тысячами кадров, ведёт игрока к радио/кораблям/телам, каждый кадр проверяет инварианты
(конечность координат, `fx<=FX_MAX`, отсутствие разрастания векторов) и отдельно детерминированно
проверяет ветку смерти игрока (враждебный пират вплотную, корпус=1). Последний прогон: 120k кадров,
0 фейлов, 0 санитайзер-ошибок. **Держи soak зелёным при правках локального режима.**
